# Parking Manager v17 — спутниковая карта и мобильный навигатор

Учебный проект на React, TypeScript и Vite. В этой версии основная работа сосредоточена на жизненном цикле бронирования, раздельном хранении пользовательских данных и подготовке Supabase.

## Основа проекта: исправления v14

### 1. Бронирования, отмены, возвраты и выезды
- У каждой новой брони уникальный идентификатор.
- Выбранное место удерживается на 10 минут, пока пользователь не оплатит бронь.
- Просроченное неоплаченное удержание отменяется и освобождает место.
- Повторная оплата одной брони блокируется дополнительной проверкой в интерфейсе.
- При отмене оплаченной, но ещё не начатой брони демо-сумма возвращается на внутренний баланс; все связанные успешные платежи помечаются как возвращённые и добавляется запись возврата.
- Активную поездку нельзя отменить как обычную бронь: сначала требуется зарегистрировать выезд.
- Выезд вручную завершает сессию и освобождает место, если на этот интервал нет другой действующей брони.
- Подтверждённая бронь, по которой не был выполнен въезд до окончания времени, отменяется; учебная оплата возвращается на демо-баланс.
- Активная сессия автоматически завершается по времени окончания брони.
- Продление проверяет пересечения, использует тариф и скидку, сохранённые в исходной брони, и списывает демо-средства.
- Напоминание создаётся за 30 минут до начала бронирования.

### 2. Состояние парковочных мест
- Для каждой парковки сохраняется отдельная схема мест.
- Карта, каталог и схема используют сохранённое состояние мест выбранной парковки.
- При переключении парковки загружается её собственная схема.
- Статусы мест в демо-режиме сохраняются в браузере. Это не данные реальных датчиков или операторов парковки.

### 3. Разделение данных пользователей
- Бронирования, автомобили, избранное, абонементы, платежные записи, способы оплаты и настройки уведомлений хранятся под ключом, связанным с нормализованным email.
- При переключении локального аккаунта данные соответствующего пользователя загружаются заново.
- Старые общие данные v13 мигрируются один раз в профиль первого локального пользователя, который их откроет. Старые записи бронирований с известным ownerEmail фильтруются по этому email.
- Новые локальные пароли хранятся в виде PBKDF2-HMAC-SHA256 хеша с уникальной солью. Старые учебные пароли мигрируются при первом успешном входе.

### 4. Supabase — необязательная облачная авторизация и синхронизация
- При наличии переменных окружения регистрация и вход используют Supabase Auth.
- Пользовательские данные интерфейса синхронизируются в `user_app_state` с привязкой к `auth.uid()` и RLS.
- SQL-схема содержит отдельные таблицы профиля, автомобилей, парковочных зон/мест, бронирований, платежей, кошелька, абонементов, пропусков, сессий, уведомлений и избранного.
- В SQL подготовлены RPC `reserve_spot`, `charge_reservation`, `demo_wallet_topup`, `refund_reservation` и `finish_reservation`; на бронирования добавлена защита от пересекающихся интервалов одного места.

**Важно:** облачная авторизация и синхронизация `user_app_state` включаются только после настройки собственного проекта Supabase. Экранные бронирования и демо-кошелёк пока работают через состояние приложения и JSON-синхронизацию; они ещё не переведены полностью на транзакционные таблицы/RPC. Поэтому версия на базе v14 подходит для учебной демонстрации, но пока не гарантирует атомарное распределение одного парковочного места между пользователями на разных устройствах.

## Запуск локально

1. Распакуйте архив.
2. Откройте в VS Code папку проекта, в которой лежит `package.json`.
3. Откройте `Terminal → New Terminal`.
4. Выполните команды по очереди:

```cmd
npm.cmd install
npm.cmd run dev
```

5. Откройте `http://localhost:5180/`.
6. Не закрывайте терминал, пока пользуетесь приложением.

Также можно дважды нажать `START_PARKING_MANAGER.bat` в корне проекта.

## Необязательная настройка Supabase

1. Создайте проект Supabase.
2. Скопируйте `.env.example` в `.env.local`.
3. Заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` значениями из настроек API вашего проекта.
4. В Supabase откройте SQL Editor и выполните `supabase/schema.sql`.
5. Перезапустите Vite после изменения `.env.local`.

В браузерный проект разрешено помещать только publishable key (или legacy anon key). **Никогда не помещайте `service_role` или secret key во frontend, ZIP для пользователей или репозиторий.**

Если `.env.local` не создан, проект работает в локальном демонстрационном режиме без облачной авторизации и синхронизации между устройствами.

## Подключение настоящей AI-поддержки

По умолчанию поддержка использует встроенные локальные сценарии ответов. Чтобы подключить настоящую модель, настройте серверный endpoint и укажите его в `VITE_AI_SUPPORT_ENDPOINT`. Endpoint должен принимать POST JSON вида `{ "message": "...", "history": [] }` и возвращать `{ "reply": "..." }` или `{ "answer": "..." }`. API-ключ модели должен храниться на сервере, не во frontend.

## Ограничения учебной версии

- Внутренний баланс, пополнения и возвраты демонстрационные; реальные деньги не переводятся.
- Статусы парковочных мест не поступают от реальных датчиков.
- Виртуальный чип и QR-пропуск не управляют физическим шлагбаумом.
- При просмотре каталога используется собственная SVG-схема; после построения маршрута навигатор показывает фактическую геометрию пути по автомобильным дорогам OSRM/OpenStreetMap.
- Фотографии парковок в каталоге иллюстративные.
- AI-поддержка не использует языковую модель, пока не настроен внешний серверный endpoint.

## Встроенный автомобильный навигатор (v16)

В разделе «Парковки» можно запросить геопозицию браузера и построить автомобильный маршрут до выбранной парковки. Для расчёта используется OSRM Route API по автомобильному графу дорог OpenStreetMap: приложение получает полную GeoJSON-геометрию пути, расстояние, расчётное время и пошаговые манёвры. Приложение само отображает геометрию маршрута внутри собственного SVG-интерфейса — не открывает сторонний сайт, iframe или картографические тайлы.

После нажатия «Начать движение» браузер отслеживает GPS через `navigator.geolocation.watchPosition`. Карта приближает текущий участок маршрута, показывает положение пользователя, подсвечивает следующий манёвр и может перестроить путь при отклонении более 90 метров. Есть голосовые подсказки на русском языке с переключателем. Для геопозиции браузер должен разрешить доступ; `localhost` считается безопасным контекстом.

**Источники и приватность:** маршрутный запрос отправляет координаты начала и выбранной парковки на настроенный OSRM endpoint. По умолчанию используется публичный `router.project-osrm.org`. Дорожные данные OpenStreetMap распространяются по ODbL и требуют атрибуции © OpenStreetMap contributors. На экране навигатора рисуется геометрия реального маршрута и подписи манёвров; окружающая подложка остаётся собственной лаконичной SVG-схемой, а не подробным городским атласом. Интерфейс маршрута и его отображение принадлежат Parking Manager, но дорожный граф не является самостоятельно собранной базой проекта.

**Ограничения:** нужен интернет. Публичный демонстрационный сервер OSRM разрешает только разумное некоммерческое использование, просит не превышать один запрос в секунду и не гарантирует доступность или задержку. В приложении запросы ограничены по частоте, автоматическое перестроение выполняется не чаще одного раза в 30 секунд. Расчёт времени не учитывает текущие пробки, ДТП и временные перекрытия; это не сертифицированный автомобильный навигатор. Не взаимодействуйте с приложением во время движения — маршрут настраивается до начала поездки.

Для стабильного развёртывания можно поднять собственный OSRM backend и указать его адрес в `VITE_ROUTING_BASE_URL` в `.env.local`. Тогда маршрутизация будет идти через ваш сервер. Для полностью офлайн-режима понадобится отдельно скачать и развернуть дорожный граф региона; одного SVG-файла карты для маршрутизации недостаточно.


## v16 — мобильный режим для iPhone

- Интерфейс адаптирован под вертикальный экран, safe areas и большие сенсорные элементы.
- При активной навигации включается отдельный экран движения: следующий манёвр сверху, карта в центре, ETA и действия в нижней панели.
- Добавлены русская озвучка, скорость речи, повтор подсказки и попытка удерживать экран активным через Screen Wake Lock API.
- Добавлены PWA manifest, иконки, standalone display и service worker для оболочки интерфейса.
- Dev-сервер слушает сетевой интерфейс (`0.0.0.0`), чтобы его можно было открыть из локальной сети; GPS на iPhone для локального IP по HTTP недоступен — для тестирования на iPhone нужен HTTPS.

Подробная инструкция и ограничения iOS: `IOS_MOBILE_GUIDE.md`. Важное ограничение: PWA не гарантирует непрерывный GPS и озвучку при сворачивании/блокировке экрана. Для этого необходим отдельный нативный iOS-клиент с Core Location background updates и AVSpeechSynthesizer.

## v17 — мобильная карта и навигация

- Добавлен режим спутниковой подложки Esri World Imagery с маркерами парковок, жестами панорамирования и pinch-to-zoom. Для спутникового слоя требуется интернет; указана атрибуция поставщика снимков.
- Добавлено раскрытие навигатора на весь экран.
- Добавлен выбор доступного системного голоса и скорости озвучки. Список голосов зависит от iPhone/браузера и установленных языковых пакетов.
- В бронировании теперь можно выбрать конкретную парковку, затем зону и свободное место.
- В схеме карты добавлено перетаскивание одним пальцем/мышью; спутниковый режим Leaflet поддерживает панорамирование и масштабирование двумя пальцами.
- В профиль добавлен понятный статус облачной синхронизации. Для синхронизации между устройствами обязательно настроить Supabase; см. `CLOUD_SYNC_SETUP.md`.

Спутниковые изображения предоставляются Esri, а маршрутизация остаётся через настроенный OSRM endpoint. Это не собственные спутниковые снимки Parking Manager. Доступность голосов зависит от операционной системы. PWA не гарантирует GPS/озвучку в фоне при заблокированном iPhone.
