# Parking Manager — постоянное хранение и автообновление

## Как будет работать
- Исходный код хранится в GitHub.
- Netlify подключается к GitHub один раз и автоматически публикует сайт после каждого push в выбранную ветку (обычно `main`).
- Supabase остаётся отдельным облачным сервисом: хранит аккаунты и данные приложения. Повторно загружать туда папку проекта при изменении интерфейса не нужно.

## Первый запуск (один раз)
1. Распакуйте архив и откройте в VS Code папку, где лежит `package.json`.
2. Создайте приватный репозиторий GitHub и загрузите туда файлы проекта. Не загружайте `.env.local`, ключи, пароли или `node_modules`. `.gitignore` уже исключает `.env.local`, `dist` и `node_modules`.
3. В Netlify выберите **Add new project → Import an existing project → GitHub**, разрешите доступ к репозиторию и выберите его.
4. Параметры сборки: команда `npm run build`, папка публикации `dist`. Они также записаны в `netlify.toml`.
5. В Netlify откройте **Project configuration → Environment variables** и добавьте переменные из Supabase: `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Используйте только publishable/anon key. Никогда не добавляйте `service_role` или secret key в клиентское приложение.
6. Запустите Deploy. После публикации откройте домен Netlify.
7. В Supabase → Authentication → URL Configuration установите домен Netlify как Site URL и добавьте его в Redirect URLs. Сохраните также локальный адрес разработки, если он уже используется.

## Как обновлять потом
1. Откройте тот же проект в VS Code.
2. Внесите изменения и проверьте локально: `npm.cmd run build`.
3. Отправьте изменения в GitHub (через Source Control в VS Code: Stage → Commit → Sync/Push).
4. Netlify автоматически соберёт и опубликует новую версию. ZIP повторно загружать не нужно.

## Что не надо делать при обычном обновлении интерфейса
- Не создавать новый проект Supabase.
- Не загружать исходный код в Supabase.
- Не создавать новый сайт Netlify.
- Не выполнять SQL повторно, если схема базы не менялась.

## Важно
- `netlify.toml` задаёт сборку Vite и SPA fallback для прямых URL.
- Supabase хранит данные отдельно от сайта. Обновление сайта само по себе не удаляет записи в Supabase.
- Если меняются SQL-таблицы или политики, миграции базы выполняются отдельно и осознанно.
- `.env.local` нужен для локальной разработки; переменные Netlify задаются в панели Netlify. Не отправляйте ключи в чат и не коммитьте `.env.local`.
